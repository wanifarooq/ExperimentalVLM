================================================================================
1. MOTIVATION AND RESEARCH QUESTION
================================================================================

Our previous paper ("Same Answer, Different Representations") showed that
Vision-Language Models (VLMs) give the same answer to a question regardless of
how the image is perturbed (translated, rotated, scaled, etc.), but the
internal representations change dramatically. This creates a paradox: if the
representations change, why doesn't the answer change?

This follow-up project answers that question by proving that the answer DOES
change -- but only when the perturbation disrupts the specific frequency bands
that the task requires. The key insight:

    A coarse task like "Is there a dog?" only needs low-frequency information
    (the general blob-shape of a dog), so it survives high-frequency
    perturbations.

    A fine task like "What color is the collar on the dog to the left of the
    cat?" needs high-frequency details (color, spatial layout, small object
    identification), so it breaks under the same perturbations.

The research question: Does the language conditioning in a VLM learn a
task-specific frequency filter, and does perturbation sensitivity scale
monotonically with task granularity?


================================================================================
2. CENTRAL HYPOTHESIS AND THEOREM
================================================================================

HYPOTHESIS:
    Language conditioning in VLMs creates a task-specific frequency filter
    W_t(omega) that determines which spatial frequency bands of the image are
    attended to. Finer tasks produce broader filters (attending to higher
    frequencies), making them more sensitive to perturbations.

THEOREM 1 (Spectral Overlap Prediction):
    The sensitivity of a VLM to a perturbation is predicted by the spectral
    overlap between the task's frequency filter and the perturbation's
    spectral signature:

        S_predicted = integral |W_t(omega)|^2 * |DeltaF(omega)|^2 d_omega

    Where:
        W_t(omega)    = task-specific frequency filter (from cross-attention)
        DeltaF(omega) = perturbation's spectral signature = |FFT(perturbed) - FFT(clean)|^2

    In plain English: a perturbation only hurts performance if it disrupts
    the frequencies the task is looking at.

WHAT THIS MEANS IN PRACTICE:
    - A 4-pixel translation (mostly high-frequency phase shift) barely
      affects "Is there a dog?" (which uses low frequencies) but might
      affect "What color is the collar?" (which needs high frequencies).
    - Low-pass filtering removes detail but preserves shapes -- it kills
      fine tasks but spares coarse ones.
    - High-pass filtering removes shapes but preserves edges -- it kills
      all tasks but affects coarse tasks more since they rely purely on
      low-frequency blob structures.

FOUR GRANULARITY LEVELS WE TEST:
    L1 (Coarse):    "Is there a {object} in this image?"       -- Y/N
    L2 (Medium):    "What {attribute} is the {object}?"        -- MCQ (color/material/shape)
    L3 (Fine):      "Is {obj1} {relation} {obj2}?"             -- Y/N spatial
    L4 (Very Fine): "What {attr} is the {obj} {rel} {obj2}?"   -- MCQ compositional

    Each level requires progressively finer image details:
    L1 only needs to detect object presence (big blob) -> low frequencies
    L4 needs attributes + spatial relations + composition -> all frequencies

3. FRAMEWORK ARCHITECTURE OVERVIEW
================================================================================

The framework is designed as a modular, YAML-configured experiment pipeline:

    [Config YAML] --> [run_experiment.py CLI]
                            |
                            v
                     [Model Adapter] -- loads VLM (Qwen/LLaVA/InternVL)
                            |
                            v
                     [Data Pipeline] -- builds 4-level questions from GQA
                            |
                            v
                     [Perturbation Engine] -- applies perturbations + spectral signatures
                            |
                            v
                     [Experiment Runner] -- one of 6 experiments
                            |
                            v
                     [Analysis Module] -- spectral, drift, overlap, statistics
                            |
                            v
                     [Plotting Module] -- publication-quality figures
                            |
                            v
                     [JSON Outputs] -- summary, hypothesis_tests, per_sample

WHY THIS DESIGN:
    - Separating model loading from experiments means we can swap models via
      config without changing experiment code.
    - The adapter pattern (VLMAdapter ABC) ensures consistent interface
      across Qwen, LLaVA, InternVL -- just change one line in the YAML.
    - Lazy imports from the parent vlm_invariance_check.py avoid duplicating
      the 6000+ line monolithic driver while reusing its battle-tested
      perturbation functions.
    - YAML config supports two profiles: default.yaml (full server run with
      1000 samples, 3 severity levels) and local_test.yaml (quick local
      validation with 10 samples, severity 1 only).

5. DATA STRUCTURES (data/base.py)
================================================================================

Three core dataclasses drive the entire framework:

(A) GranularityLevel (IntEnum)
    --------------------------------
    L1_COARSE    = 1   # Object presence / whole-object segmentation
    L2_MEDIUM    = 2   # Attribute recognition / part-level segmentation
    L3_FINE      = 3   # Spatial relationship / subpart segmentation
    L4_VERY_FINE = 4   # Compositional MCQ reasoning

    WHY AN INTENUM: We use integer values (1-4) as numerical granularity
    ranks in Spearman correlation. Higher value = finer task = more
    frequency bands needed = more sensitive to perturbations.

(B) LevelData
    --------------------------------
    Fields:
        level          : GranularityLevel  -- which granularity this is
        question       : str               -- the actual question text
        options        : Dict[str,str]     -- MCQ options {"A":"yes","B":"no"} etc
        answer_label   : str               -- ground truth label ("A", "B", etc)
        mask_path      : Path              -- for segmentation experiments (Exp 6)
        text_prompt    : str               -- for SAM3 text-conditioned segmentation
        question_type  : str               -- metadata like "object_presence", "attribute_color"

    WHY THIS STRUCTURE: Every experiment needs to score a task on an image.
    Whether it's VQA (Exp 1-5) or segmentation (Exp 6), the interface is:
    given an image + task description, measure performance. LevelData
    captures both MCQ and segmentation tasks uniformly.

(C) GranularitySample
    --------------------------------
    Fields:
        image_id  : str
        image_path: Path
        levels    : Dict[GranularityLevel, LevelData]  -- L1 through L4 tasks
        dataset   : str    -- "gqa", "partimagenet", "seedbench"
        split     : str    -- "val", "train"
        metadata  : dict   -- arbitrary (e.g. {"num_objects": 12})

    KEY PROPERTY: has_all_levels() -- we ONLY keep samples where all 4
    granularity levels could be constructed. This ensures every comparison
    is within-image: the SAME image is asked coarse and fine questions,
    so any performance difference is due to the task, not the image.

(D) ExperimentResult
    --------------------------------
    Fields:
        experiment_id    : int
        experiment_name  : str
        config           : dict
        metrics          : dict    -- summary numbers
        per_sample       : list    -- per-image detail records
        hypothesis_tests : dict    -- statistical test results

    This is what each experiment's run_expN() function returns.
    The runner saves it to JSON and passes it to downstream experiments.

6. MODEL ADAPTER LAYER (models/)
================================================================================

(A) WHY WE NEED AN ADAPTER
    The existing vlm_invariance_check.py has model loading buried in a 6000-line
    monolithic file. We need to:
    1. Load the model once and reuse it across experiments
    2. Extract INTERNAL representations (attention maps, hidden states) that
       the original code never accessed
    3. Support multiple model families (Qwen, LLaVA, InternVL) with the
       same interface
    4. Hook into specific layers without modifying model code

(B) VLMAdapter ABC (models/base.py)
    Abstract base class with these methods:

    load(model_id, device, quantization)  -- load model onto GPU
    unload()                               -- free GPU memory
    score_options(image, question, options) -- MCQ log-likelihood scoring
    generate(image, prompt)                -- open-ended text generation
    extract_internals(image, prompt, ...)  -- THE KEY NEW METHOD
    get_vision_tokens(image)               -- raw vision encoder output
    get_patch_grid_shape(image)            -- (H_patches, W_patches)

(C) HookOutputs dataclass (models/base.py)
    Container for everything we extract from the model's forward pass:

    cross_attention_weights : List[Tensor]  -- per-layer (heads, lang, vis)
    pre_fusion_features     : Tensor        -- vision encoder output (before LLM)
    post_fusion_features    : Tensor        -- after first decoder layers
    patch_grid              : (H, W)        -- spatial layout of vision tokens
    vision_token_range      : (start, end)  -- position in input sequence

(D) QwenVLAdapter (models/qwen_adapter.py)

    CRITICAL ARCHITECTURE DETAIL:
    Qwen VL models do NOT have separate cross-attention layers like classic
    encoder-decoder models. Instead:

    1. The vision encoder produces a grid of patch tokens
    2. These tokens are projected and CONCATENATED with text tokens
    3. The combined sequence goes through standard self-attention layers
    4. "Cross-attention" is the sub-matrix where text tokens attend to
       vision tokens within the self-attention

    HOW WE EXTRACT CROSS-ATTENTION:
    - Find vision token positions using <|vision_start|> and <|vision_end|>
      special tokens in the input_ids
    - Pass output_attentions=True to the forward call
    - From the full attention matrix (seq_len x seq_len), slice:
        cross_attn = full_attn[:, lang_positions, vision_positions]
      This gives us (heads, num_lang, num_vis) -- effective cross-attention

    HOW WE EXTRACT PRE/POST FUSION FEATURES:
    - Pre-fusion: register_forward_hook on model.model.visual (vision encoder)
    - Post-fusion: register_forward_hook on model.model.layers[2] (early decoder)
    - The hooks capture the output tensors and store them in a dict
    - After the forward pass, we collect them into HookOutputs

    MCQ SCORING (score_options):
    For each option in the MCQ:
    1. Build prompt: question + "\n" + option_text
    2. Run forward pass to get logits
    3. Compute log-probability of the option tokens at the end of the sequence
    4. Sum log-probs over all tokens of the option
    5. The option with highest total log-prob is the model's "answer"

    This is a standard log-likelihood MCQ evaluation approach used in
    LLM/VLM benchmarks.

(E) get_adapter() factory (models/__init__.py)
    Takes a model_id string and returns the appropriate adapter:
    - "Qwen" in name -> QwenVLAdapter
    - "llava" in name -> LlavaAdapter (not yet implemented)
    - "internvl" in name -> InternVLAdapter (not yet implemented)

7. GQA DATA PIPELINE (data/gqa.py)
================================================================================

GQA (Visual Genome Question Answering) is a dataset with ~113K images and
rich scene graph annotations. Each image has:
    - objects: {id: {name, x, y, w, h, attributes[], relations[]}}
    - relations: links between objects (e.g., "dog" -> "to the left of" -> "cat")

WHY GQA:
    Unlike VQA or other benchmarks, GQA has structured scene graphs that let
    us GENERATE questions at controlled granularity levels. We don't use the
    pre-made GQA questions -- we build our own from the scene graph to ensure
    exact granularity control.

QUESTION GENERATION (build_l1_question through build_l4_question):

    L1 (Coarse) - Object Presence:
        Template: "Is there a {object_name} in this image?"
        Answer: "yes" if object exists in scene graph, "no" for absent objects
        Options: {"A": "yes", "B": "no"}
        Ratio: 80% positive (present objects), 20% negative (absent objects)

        WHY THIS IS COARSE: Only needs to detect a blob of the right class.
        A rough silhouette or shape is sufficient. Low-frequency information.

    L2 (Medium) - Attribute Recognition:
        Template: "What {category} is the {object}?"
        Answer: The correct attribute (e.g., "red" for color)
        Options: 4-way MCQ with 3 distractors from same category
        Categories: color, material, shape, size, texture

        WHY THIS IS MEDIUM: Needs to not just detect the object but
        identify a specific visual property. Colors require moderate
        frequency detail; materials/textures need more.

    L3 (Fine) - Spatial Relationship:
        Template: "Is the {obj1} {relation} the {obj2}?"
        Answer: "yes" for true relations from scene graph, "no" for false
        Relations: "to the left of", "above", "behind", etc.
        Ratio: 70% positive, 30% negative (substituted wrong relation)

        WHY THIS IS FINE: Must locate two specific objects AND determine
        their spatial arrangement. Requires higher-frequency spatial
        information to distinguish relative positions.

    L4 (Very Fine) - Compositional MCQ:
        Template: "What {attribute} is the {object} that is {relation} the {other_object}?"
        Answer: Correct attribute of the compositionally-referenced object
        Options: 4-way MCQ

        WHY THIS IS VERY FINE: Combines attribute recognition WITH spatial
        relation. Must find the right object using a spatial reference,
        THEN identify its attribute. Requires both high spatial resolution
        (to resolve which object is where) and detail (to identify attributes).

    FILTERING: Only images where ALL 4 levels can be constructed are kept.
    This requires the scene graph to have objects with attributes AND
    relations. About 10-20% of GQA images qualify.

ON-DEMAND IMAGE DOWNLOADING:
    GQA images are from Visual Genome (~20 GB full set). Instead of
    downloading everything, we download individual images on demand:
    - Try: https://cs.stanford.edu/people/rak248/VG_100K/{id}.jpg
    - Try: https://cs.stanford.edu/people/rak248/VG_100K_2/{id}.jpg
    This makes testing with 3-10 images fast without a 20 GB download.

8. PERTURBATION ENGINE (perturbations/)
================================================================================

(A) WHAT IT DOES
    Takes a clean image and produces a list of PerturbationResult objects,
    each containing:
    - The perturbed image
    - The perturbation's spectral signature DeltaF(omega)
    - Metadata (name, family, severity)

(B) PerturbationResult dataclass:
    name            : str          -- e.g. "Translation(+4)|sev1"
    family          : str          -- "natural", "lowfreq", or "highfreq"
    severity        : int          -- 1 (mild), 2 (moderate), 3 (severe)
    perturbed_image : PIL.Image
    delta_f         : ndarray      -- shape (num_bands,), radially binned spectral signature
    delta_f_2d      : ndarray      -- shape (H, W), full 2D spectral difference

(C) PERTURBATION TYPES (13 total per severity level):

    NATURAL PERTURBATIONS (12 types):
    These are geometric/overlay transforms that don't explicitly target
    specific frequencies but have characteristic spectral signatures:

    1.  Translation(+N)       -- cyclic horizontal shift right by N pixels
    2.  Translation(-N)       -- cyclic horizontal shift left by N pixels
    3.  PadCrop(+N)           -- pad N pixels on one side, crop N from other
    4.  PadCrop(-N)           -- opposite direction
    5.  Scale(s)              -- resize by factor s (e.g. 0.95 = 5% smaller)
    6.  ScalePadBlack(s)      -- scale + pad with black to original size
    7.  ScalePadWhite(s)      -- scale + pad with white to original size
    8.  Rotation(+deg)        -- rotate clockwise by deg degrees
    9.  Rotation(-deg)        -- rotate counter-clockwise
    10. TextOverlay            -- overlay "SAMPLE TEXT" on image
    11. BoxOverlay             -- draw a rectangle overlay
    12. RandomText             -- overlay random number text

    FREQUENCY PERTURBATIONS (5 types):
    These explicitly target frequency bands:

    13. LowPassKeep(cutoff)   -- keep only frequencies below cutoff (blur)
    14. HighPassKeep(cutoff)   -- keep only frequencies above cutoff (edges only)
    15. LowBandNoise(cutoff)  -- add noise only in low-frequency bands
    16. HighBandNoise(cutoff)  -- add noise only in high-frequency bands
    17. AllBandNoise(cutoff)   -- add noise across all frequency bands

    TOTAL: At severity 1 alone: 12 natural + 5 frequency = 17 perturbations.
    (In practice the code generates 13 because some share implementation.)
    At 3 severity levels: 17 x 3 = 51 perturbations per image.

(D) SEVERITY PARAMETERS:
    Severity 1 (mild):     translate=4px, scale=0.95, rotation=10deg, freq_cutoff=0.18
    Severity 2 (moderate): translate=8px, scale=0.90, rotation=20deg, freq_cutoff=0.28
    Severity 3 (severe):   translate=12px, scale=0.85, rotation=30deg, freq_cutoff=0.38

(E) SPECTRAL SIGNATURE COMPUTATION (compute_spectral_signature):
    For every perturbation, we compute HOW it changes the frequency content:

    1. Convert clean and perturbed images to grayscale float [0,1]
    2. Compute 2D FFT of each
    3. Difference: delta = FFT(perturbed) - FFT(clean)
    4. Power: |delta|^2
    5. Shift zero-frequency to center (fftshift)
    6. Radially bin into num_bands (default 10) concentric rings
    7. Average power within each ring

    Result: delta_f has shape (10,) -- energy of the perturbation at each
    frequency band from DC (band 0) to Nyquist (band 9).

    WHY THIS MATTERS: This is one half of Theorem 1. We need DeltaF(omega)
    to multiply with W_t(omega) for predicting sensitivity.

(F) FREQUENCY SWEEP (perturbations/frequency_sweep.py):
    Used by Experiment 4. Generates a sequence of lowpass or highpass
    filtered images at linearly spaced cutoff frequencies:

    cutoffs = linspace(0.02, 0.5, num_steps)  -- 20 steps default

    For each cutoff:
    - lowpass: keep only frequencies below cutoff (progressive blur)
    - highpass: keep only frequencies above cutoff (progressive edge-only)

    Returns list of (cutoff, filtered_image) pairs.


================================================================================
9. ANALYSIS MODULES (analysis/)
================================================================================

Four analysis modules contain the core scientific computations:

(A) analysis/spectral.py -- NOVEL: Frequency structure of cross-attention

    attention_to_spatial_grid(attention, patch_grid):
        Takes flattened attention vector (..., num_vis_tokens) and reshapes
        to (..., H_patches, W_patches). Handles CLS token mismatches by
        padding or truncating.

        WHY: VLM attention is over a flat sequence of vision tokens, but
        frequency analysis needs a 2D spatial layout.

    compute_attention_power_spectrum(attention_2d, num_bands=10):
        Input: 2D attention map (H, W)
        Process:
            1. 2D FFT of the attention map
            2. Shift zero-frequency to center
            3. Compute power: |FFT|^2
            4. Create distance map from center (frequency magnitude)
            5. Bin into num_bands concentric rings
            6. Average power in each ring
        Output: (radial_power, full_power_2d)

        WHY: This converts the spatial attention pattern into a frequency
        profile. If attention is a smooth blob (low-pass), power
        concentrates in low bands. If attention is scattered/detailed
        (high-pass), power spreads to high bands.

    compute_attention_power_spectrum_multi(attention_maps, patch_grid, num_bands):
        Averages power spectra across all attention heads and layers.
        Handles different input shapes:
        - 1D: single attention vector
        - 2D: (lang_tokens, vis_tokens) -- averages over lang tokens first
        - 3D: (heads, lang_tokens, vis_tokens) -- processes each head

        WHY: A single head might be noisy. Averaging across heads and
        layers gives a stable estimate of the task's frequency profile.

    compute_effective_bandwidth(power_spectrum):
        Input: radial power spectrum (num_bands,)
        Formula: G(t) = (sum |W|^2)^2 / (sum |W|^4)
        This is the inverse participation ratio.

        Range: 1.0 (all energy in one band) to num_bands (uniform energy)

        WHY: G(t) is a single number summarizing whether the task uses
        narrow (low) or broad (high) frequency support. Our hypothesis
        predicts G(L1) < G(L2) < G(L3) < G(L4).

    compute_filter_W_t(radial_power):
        Normalizes radial power to sum to 1.
        W_t(omega) = radial_power / sum(radial_power)

        WHY: W_t is the task-specific frequency filter -- the probability
        distribution over frequency bands showing where the task "looks."
        This is THE core novel quantity we're computing.

    compute_spectral_overlap(W_t, delta_f):
        Formula: S_pred = sum |W_t(omega)|^2 * |DeltaF(omega)|^2

        WHY: This is Theorem 1. If W_t is concentrated at low frequencies
        and DeltaF is at high frequencies, the overlap is small (low
        sensitivity). If they overlap, sensitivity is high.

(B) analysis/drift.py -- NOVEL: Pre/post fusion drift decomposition

    compute_band_drift(clean_features, perturbed_features, num_bands):
        Input: feature tensors (num_tokens, hidden_dim)
        Process:
            1. Compute difference: perturbed - clean
            2. Reshape to 2D spatial grid (assuming square layout)
            3. Compute norm across hidden dim -> spatial drift map
            4. 2D FFT of the drift map
            5. Radially bin into frequency bands
        Output: band-decomposed drift energy (num_bands,)

        WHY: We need to know which frequency bands carry the perturbation
        signal through the model. If band 3 has high drift pre-fusion but
        low drift post-fusion, the model is suppressing that frequency.

    compute_amplification_ratio(pre_drift, post_drift):
        Formula: R(omega) = post_drift(omega) / pre_drift(omega)
        Per-band ratio showing amplification (>1) or suppression (<1).

        WHY: R(omega) reveals what the language conditioning DOES to
        perturbation signals. If R correlates with W_t, it means the
        model amplifies drift exactly in the bands it attends to --
        confirming that language conditioning creates a frequency filter.

    compute_scalar_drift(clean, perturbed):
        Simple mean L2 distance across tokens.

    compute_cosine_drift_per_token(clean, perturbed):
        Per-token cosine distance (1 - cos_sim).

(C) analysis/overlap.py -- NOVEL: Theorem 1 validation

    predict_sensitivities(W_t_per_level, perturbation_spectra):
        For each (level, perturbation) pair, computes predicted sensitivity
        using spectral overlap.

        Returns: {level: [(pert_name, predicted_sensitivity), ...]}

    load_actual_sensitivities_from_exp1(exp1_summary):
        Extracts measured accuracy drops from Experiment 1 results.

        Returns: {level: {pert_name: mean_accuracy_drop}}

    match_predictions_to_actuals(predictions, actuals):
        Aligns predicted and actual values into paired arrays for
        correlation analysis. Only includes pairs present in both.

        Returns: (predicted_array, actual_array, labels)

(D) analysis/statistics.py -- Standard statistical tests

    spearman_correlation(x, y):    Spearman rank correlation + p-value
    pearson_correlation(x, y):     Pearson linear correlation + p-value
    one_way_anova(*groups):        F-statistic + p-value
    cohens_d(group1, group2):      Effect size (pooled std)
    paired_ttest(x, y):            Paired t-test
    monotonicity_test(values):     Kendall's tau + monotonicity check
    bootstrap_ci(data, n_boot):    95% confidence interval via bootstrap

    WHY THESE SPECIFIC TESTS:
    - Spearman: our hypothesis is about monotonic ordering, not linearity
    - ANOVA: tests if levels differ significantly (not just monotonically)
    - Cohen's d: quantifies effect size (is the difference meaningful?)
    - Bootstrap CI: non-parametric confidence bounds with small samples
    - Kendall's tau: specifically tests ordinal association

10. EXPERIMENT 1: TASK GRANULARITY SPECTRUM
================================================================================

FILE: experiments/exp1_granularity.py (21 KB -- the largest experiment)
PURPOSE: Establish that VLM sensitivity scales with task granularity.

ALGORITHM:
    1. Load VLM (Qwen3-VL-8B or 2B for local testing)
    2. Build GQA dataset (1000 samples with all 4 granularity levels)
    3. For each sample:
        a. Open image
        b. Build perturbation suite (17 perturbations x 3 severities = 51)
        c. For each granularity level (L1-L4):
            i.   Score MCQ on CLEAN image -> get log-likelihoods per option
            ii.  Record if predicted label matches ground truth (clean accuracy)
            iii. For each perturbation:
                 - Score MCQ on PERTURBED image
                 - Record accuracy drop: 1 if correct->wrong, 0 otherwise
                 - Record loglik drift: clean_loglik - perturbed_loglik
                 - Record spectral signature stats (delta_f norm, peak band)
    4. Aggregate by (level, perturbation):
        - mean_accuracy_drop, std_accuracy_drop per level
        - mean_loglik_drift per level
        - clean_accuracy, perturbed_accuracy per level
    5. Run hypothesis tests (see below)

KEY HELPER FUNCTIONS:
    _predict_label(scores):   argmax over log-likelihood scores
    _is_correct(scores, gt):  check if argmax matches ground truth
    _compute_cosine_drift():  cosine distance between clean/perturbed vision tokens
    _evaluate_sample():       the inner loop -- evaluates one image across all levels
    _aggregate_results():     collects per-sample data into per-level statistics
    _run_hypothesis_tests():  runs all statistical tests

HYPOTHESIS TESTS:
    H1: Spearman rho(granularity_rank, mean_accuracy_drop) > 0.8
        "Finer tasks degrade more" -- the core claim

    H2: Monotonicity of mean_accuracy_drop across levels (Kendall tau > 0.6)
        "L1 drop < L2 drop < L3 drop < L4 drop"

    H3: ANOVA F > 10, p < 0.001
        "The four levels are significantly different groups"

    H4: Cohen's d > 0.8 between L1 and L4
        "The effect is large, not just statistically significant"

    H5: Bootstrap 95% CI on each level's mean degradation
        "The estimates are stable, not driven by outliers"

OUTPUTS:
    exp1/summary.json              -- per_level and per_level_perturbation stats
    exp1/hypothesis_tests.json     -- all test results with pass/fail
    exp1/per_sample.jsonl          -- one JSON per line, full per-image detail
    exp1/degradation_by_level.json -- (level x perturbation) breakdown

WHY THIS EXPERIMENT IS IMPORTANT:
    This is the empirical foundation. Without showing that sensitivity
    actually scales with granularity, the entire theory is unfounded.
    Every subsequent experiment builds on this result.

11. EXPERIMENT 2: CROSS-ATTENTION FREQUENCY ANALYSIS
================================================================================

FILE: experiments/exp2_attention_frequency.py (12 KB)
PURPOSE: Extract W_t(omega) -- the task-specific frequency filter.

ALGORITHM:
    1. Load VLM with attention hooks installed
    2. For each sample (200 images) x each level prompt:
        a. Run extract_internals(image, prompt, extract_attention=True)
        b. Get cross_attention_weights: list of (heads, lang, vis) per layer
        c. Reshape attention to spatial grid: (vis_tokens) -> (H_patches, W_patches)
        d. Compute 2D FFT -> power spectrum |A_hat(omega)|^2
        e. Radially average -> 1D power spectrum (10 bands)
        f. Normalize -> W_t(omega) (sums to 1)
        g. Compute effective bandwidth G(t) = inverse participation ratio
    3. Average W_t across samples per level
    4. Save per-sample W_t to .npy files (used by Exp 3 and 5)
    5. ANOVA on G(t) across levels

KEY INSIGHT:
    When the VLM processes "Is there a dog?" (L1), its attention over
    vision tokens should form a smooth spatial pattern (low-frequency W_t).
    When processing "What color is the collar on the dog to the left of the
    cat?" (L4), attention should be more scattered and detailed
    (high-frequency W_t).

HYPOTHESIS TEST:
    ANOVA on G(t): F > 10, p < 0.001
    G(L1) < G(L2) < G(L3) < G(L4)

OUTPUTS:
    exp2/summary.json               -- per_level W_t averages and G(t) stats
    exp2/filters/{id}_{level}.npy   -- per-sample W_t arrays (for Exp 3, 5)
    exp2/power_spectra.json         -- per-sample power spectrum data

MEMORY CONCERN:
    output_attentions=True retains full attention matrices for all layers.
    For a 28-layer model with 2048 seq_len: 28 * 32 * 2048 * 2048 * 4 bytes
    = ~14 GB. Mitigated by layer_stride=4 (extract every 4th layer) and
    processing one sample at a time.

12. EXPERIMENT 3: PRE/POST FUSION DRIFT
================================================================================

FILE: experiments/exp3_fusion_drift.py (13 KB)
PURPOSE: Show that language conditioning amplifies drift in attended bands.
DEPENDS ON: Experiment 2 (needs W_t filters)

ALGORITHM:
    1. Load W_t filters from Experiment 2 output
    2. For each sample x perturbation:
        a. Hook vision encoder output -> pre_fusion features V
        b. Hook early decoder layer output -> post_fusion features Z
        c. Run model on CLEAN image -> V_clean, Z_clean
        d. Run model on PERTURBED image -> V_perturbed, Z_perturbed
        e. Compute band-decomposed drift at pre-fusion:
            DeltaV(omega) = FFT(V_perturbed - V_clean) radially binned
        f. Compute band-decomposed drift at post-fusion:
            DeltaZ(omega) = FFT(Z_perturbed - Z_clean) radially binned
        g. Amplification ratio: R(omega) = ||DeltaZ(omega)|| / ||DeltaV(omega)||
    3. For each level, correlate R(omega) with W_t(omega) from Exp 2

WHAT R(omega) TELLS US:
    - R(omega) > 1 at band omega: fusion AMPLIFIED the perturbation signal
    - R(omega) < 1 at band omega: fusion SUPPRESSED it
    - R(omega) ~ 1: fusion passed it through unchanged

    If R(omega) correlates with W_t(omega), it means:
    "The model amplifies perturbation effects exactly in the frequency
    bands it's paying attention to."

    This is the mechanistic explanation for why fine tasks are more
    sensitive: they attend to more bands (broader W_t), so they amplify
    drift across more frequencies, leading to larger total drift at the
    output, leading to more answer changes.

HYPOTHESIS TEST:
    Pearson r(R(omega), W_t(omega)) > 0.6

OUTPUTS:
    exp3/summary.json           -- per_level amplification ratios and correlation
    exp3/hypothesis_tests.json  -- R vs W_t correlation results
    exp3/amplification.json     -- per-sample amplification data

13. EXPERIMENT 4: SYNTHETIC FREQUENCY ABLATION
================================================================================

FILE: experiments/exp4_frequency_ablation.py (9.6 KB)
PURPOSE: Find the critical frequency cutoff for each granularity level.

ALGORITHM:
    1. Generate 20 cutoff values from 0.02 to 0.50 (normalized frequency)
    2. For each sample:
        For each cutoff:
            For lowpass mode:
                - Remove all frequencies above cutoff (progressive blur)
                - Score MCQ at each level
            For highpass mode:
                - Remove all frequencies below cutoff (progressive edge-only)
                - Score MCQ at each level
    3. For each level, find critical cutoff omega_c* where accuracy = 50%
       (by linear interpolation on the accuracy-vs-cutoff curve)
    4. Test monotonicity of omega_c* across levels

INTUITION:
    Lowpass experiment:
    - At cutoff = 0.02 (almost DC only): all levels fail (image is a blur)
    - As cutoff increases, accuracy recovers level by level
    - L1 recovers FIRST (needs only low frequencies)
    - L4 recovers LAST (needs high frequencies too)
    - So omega_c*(L1) < omega_c*(L2) < omega_c*(L3) < omega_c*(L4)

    Highpass experiment:
    - At cutoff = 0.50 (keep everything): all levels at baseline
    - As cutoff increases (removing more low frequencies):
    - L1 dies FIRST (relied purely on low frequencies)
    - L4 dies LAST (had distributed frequency support)

HYPOTHESIS TEST:
    omega_c*(L1) < omega_c*(L2) < omega_c*(L3) < omega_c*(L4) for lowpass
    Spearman rho(level, omega_c*) > 0.8

OUTPUTS:
    exp4/summary.json           -- critical cutoffs per level per mode
    exp4/accuracy_curves.json   -- full accuracy-vs-cutoff data for plotting
    exp4/hypothesis_tests.json  -- monotonicity and correlation results

14. EXPERIMENT 5: SPECTRAL OVERLAP PREDICTION
================================================================================

FILE: experiments/exp5_overlap_prediction.py (11 KB)
PURPOSE: Validate Theorem 1 -- does spectral overlap predict sensitivity?
DEPENDS ON: Experiment 1 (actual sensitivities) AND Experiment 2 (W_t filters)

ALGORITHM:
    1. Load W_t filters from Experiment 2 (per level)
    2. Load perturbation spectral signatures DeltaF from Experiment 1
    3. Load actual accuracy drops from Experiment 1
    4. For each (level, perturbation) pair:
        predicted = sum |W_t(omega)|^2 * |DeltaF(omega)|^2
        actual    = measured accuracy drop from Exp 1
    5. Compute Pearson r(predicted, actual)
    6. Generate scatter plot data (predicted vs actual)

WHY THIS IS THE KEY EXPERIMENT:
    Experiments 1-4 show correlations and trends. Experiment 5 provides
    QUANTITATIVE PREDICTION. If we can predict sensitivity from spectral
    overlap, it validates the entire theoretical framework:

    "You don't need to run the model to know if a perturbation will
    affect performance. Just compute spectral overlap between the
    task's attention filter and the perturbation's frequency signature."

    This has practical implications: you can pre-screen perturbations
    for robustness without expensive model inference.

HYPOTHESIS TEST:
    Pearson r > 0.7 between predicted and actual sensitivity

OUTPUTS:
    exp5/summary.json         -- correlation metrics (pearson_r, spearman_rho)
    exp5/hypothesis_tests.json
    exp5/scatter_data.json    -- [(predicted, actual, label), ...] for plotting

FILE: experiments/exp6_segmentation_granularity.py (12 KB)
PURPOSE: Extend the theory to segmentation tasks using SAM2 and SAM3.

================================================================================
23. KNOWN GOTCHAS AND ENVIRONMENT NOTES
================================================================================

1. prepare_model() expects device as STRING, not torch.device object.
   The adapter converts: device_str = str(device)

2. Qwen3-VL processor requires torchvision (for AutoVideoProcessor).
   Install: pip install torchvision

3. System Python (Ubuntu 24.04+) is externally managed:
   pip install --user --break-system-packages {package}

4. scale_and_pad() uses background="black" not pad_color=(0,0,0).

5. Qwen VL has NO separate cross-attention. Must slice self-attention:
   cross_attn = full_attn[:, lang_positions, vision_start:vision_end]

6. Vision tokens are bracketed by <|vision_start|> / <|vision_end|>
   special tokens in the input_ids sequence.

7. GQA images download on demand from Visual Genome -- no need for the
   full 20 GB images.zip download for testing.

8. output_attentions=True is memory-intensive. Use layer_stride > 1
   for large models to avoid OOM.

9. The 2B model is good for pipeline testing but too weak for meaningful
   results. Use 8B+ for real experiments.

10. bitsandbytes is needed for 4-bit quantization but optional for 2B.
