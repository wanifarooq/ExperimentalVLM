Project: Follow-up to "Same Answer, Different Representations" (VLM Robustness)

================================================================================
1. CURRENT SCIENTIFIC CLAIM
================================================================================

The project tests whether language conditioning in VLMs creates a task-specific
frequency filter W_t. Robustness is predicted by overlap between:

    1. W_t(omega): the task-conditioned attention/filter spectrum
    2. DeltaF(omega): the perturbation spectrum

The current code adds a two-factor language model around that core claim:

    - residualized semantic logic increases spectral grounding demand
    - prompt load can act as linguistic anchoring
    - option hardness controls MCQ discrimination difficulty
    - prediction entropy controls clean-answer uncertainty

The headline Exp 5 target is now correct-answer log-likelihood volatility,
not raw accuracy drop. Accuracy drop, net drop, relative accuracy drop, and
log-likelihood erosion remain control targets.


================================================================================
2. IMPLEMENTED LEVELS
================================================================================

The GQA loader builds same-image tasks from scene graphs.

Primary levels:

    L1: object presence, yes/no
    L2: attribute query, MCQ
    L3: spatial relationship verification, yes/no
    L4: compositional attribute query under a relation, MCQ

Wordy mirror controls:

    L5: wordy mirror of L1 semantics
    L6: wordy mirror of L2 semantics
    L7: wordy mirror of L3 semantics
    L8: wordy mirror of L4 semantics

Important current behavior:

    - L5-L8 copy the matched base semantic program.
    - L5-L8 use neutral filler to increase prompt load.
    - L5-L8 are not padded to exactly 60 content words.
    - The only requirement is that the wordy prompt is longer than the matched
      base prompt by at least `_WORDY_MIN_EXTRA_PROMPT_CONTENT_WORDS`.
    - Cache version is `gqa_multilevel_v5`.
    - Verification tasks are balanced toward 50% yes and 50% no when possible.
    - Dataset construction stops early once the requested balanced target is met.

The primary monotonic granularity tests are still interpreted on L1-L4. L5-L8
are controls for prompt load and linguistic anchoring.

Aggregation views:

    primary: L1-L4 only
    wordy:   L5-L8 only
    pooled:  L1-L8

These views are defined once in `analysis/level_views.py`. Regressions and
grouped overlap correlations emit view-specific payloads where applicable.
Legacy unsuffixed JSON keys remain for compatibility. Monotonicity/Spearman
granularity tests are not pooled.


================================================================================
3. KEY DATA FIELDS
================================================================================

Every VQA level stores both discrete labels and continuous controls:

    complexity_score
        Structured semantic program score.

    prompt_complexity_score
        Prompt-load proxy based on content words / prompt atoms.

    complexity_score_residual
        Main semantic variable for horse-race plots and regressions. It is the
        residualized logic score after accounting for prompt load. The fit is
        learned on primary levels and applied to wordy mirrors.

    option_hardness_score
        MCQ-distractor difficulty control.

    prediction_entropy
        Clean-image softmax entropy over MCQ option scores.

    clean_accuracy
        Clean correctness indicator. Accuracy-drop regressions are gated to
        clean-correct points where appropriate, so they measure fragility of
        existing knowledge rather than already-wrong examples.

Correct-answer log-likelihood drift metrics:

    loglik_drift = clean_ll(correct) - perturbed_ll(correct)
    loglik_erosion = max(loglik_drift, 0)
    loglik_recovery = min(loglik_drift, 0)
    loglik_volatility = abs(loglik_drift)

Interpretation:

    - positive drift means the correct answer lost confidence
    - negative drift means the correct answer recovered confidence
    - volatility ignores sign and measures total confidence motion


================================================================================
4. MODEL ADAPTERS
================================================================================

The main adapter interface is `models/base.py`.

Implemented/current model families:

    - Qwen/Qwen3-VL-* through `QwenAdapter`
    - llava-hf/llava-v1.6-mistral-7b-hf through the shared HF path
    - OpenGVLab/InternVL3-8B-hf through the shared HF path

Primary profiles:

    - local smoke: Qwen/Qwen3-VL-2B-Instruct
    - server: Qwen/Qwen3-VL-30B-A3B-Instruct with device_map: auto

Qwen implementation detail:

    Qwen3-VL concatenates projected vision tokens and text tokens into one
    decoder sequence. There is no separate encoder-decoder cross-attention
    module. The code extracts effective language-to-vision attention by slicing
    self-attention from non-vision query positions to vision-key positions.

Processor compatibility:

    Newer Transformers versions require image-processor kwargs under
    `processor_kwargs`. The adapter uses compatibility handling so newer server
    installs do not emit repeated processor warning spam.


================================================================================
5. PERTURBATIONS
================================================================================

Perturbations are configured under `perturbations` in YAML.

Natural families:

    translation
    padcrop
    scale
    scalepad_black
    scalepad_white
    rotation
    text_overlay
    box_overlay
    random_text

Frequency families:

    lowpass_keep
    highpass_keep
    lowband_noise
    highband_noise
    allband_noise

Current overlay behavior:

    - overlay_mode defaults to `label_free`
    - text, random text, and box overlays are nuisance perturbations
    - they are not answer-conditioned
    - severity controls overlay size/strength when the family is enabled

Example-image export:

    `perturbations.export_num_images` saves clean plus all perturbations for
    the first N successful samples per supported experiment.

Spectral signatures:

    - image-space spectra are stored as `delta_f` and `delta_f_relative`
    - vision-feature spectra are stored as `delta_f_vision` and
      `delta_f_vision_relative` when feature extraction is enabled
    - relative spectra normalize perturbation energy by original-image energy


================================================================================
6. SPECTRAL SETTINGS
================================================================================

Band count:

    `analysis.num_bands_mode: auto` probes the model patch grid, estimates a
    reasonable linear radial band count, and freezes that count for the run.
    This keeps W_t, DeltaF, Exp 3 drift spectra, and Exp 5 overlap vectors
    aligned.

DC band:

    `analysis.suppress_dc` controls whether band 0 is included in the math.
    The provided configs currently keep DC enabled with `suppress_dc: false`.

Attention FFT window:

    `analysis.attention_fft_window` and `experiments.exp2.fft_window` support
    `hann`, `hamming`, and off values `none` / `off` / `false`. The provided
    configs currently use `none`.

Visualization:

    Plotting can use log scaling only for visualization when configured. This
    does not change the stored spectra, overlap calculation, or hypothesis
    tests.

7. EXPERIMENT 1 -- TASK GRANULARITY SPECTRUM
================================================================================

Main file: `experiments/exp1_granularity.py`

What it does:

    1. Builds same-image GQA samples with L1-L8 when possible.
    2. Scores clean MCQ options by continuation log-likelihood.
    3. Applies configured perturbations.
    4. Scores perturbed images.
    5. Stores accuracy, net drop, relative drop, and directional
       log-likelihood drift metrics.
    6. Stores image-space DeltaF and optionally vision-feature DeltaF.

Important statistical behavior:

    - continuous complexity points are stored in `complexity_points.json`
    - horse races use `complexity_score_residual` as the semantic variable
    - horse races are emitted for primary, wordy, and pooled views
    - prompt load, option hardness, clean accuracy, and prediction entropy are
      controls where appropriate
    - accuracy-drop horse races are filtered to clean-correct points
    - perturbation-specific horse races are emitted for accuracy and
      log-likelihood outcomes
    - paired mirror tests compare L1/L5, L2/L6, L3/L7, and L4/L8

Primary outputs:

    exp1/summary.json
    exp1/hypothesis_tests.json
    exp1/per_sample.jsonl
    exp1/complexity_points.json
    exp1/degradation_by_level.json
    exp1/perturbation_examples/


================================================================================
8. EXPERIMENT 2 -- ATTENTION FREQUENCY ANALYSIS
================================================================================

Main file: `experiments/exp2_attention_frequency.py`

What it does:

    1. Extracts effective language-to-vision attention from model self-attention.
    2. Builds 2D patch-grid attention maps.
    3. Optionally applies FFT windowing.
    4. Computes radial power spectra.
    5. Normalizes spectra into W_t.
    6. Computes effective bandwidth with inverse participation ratio.
    7. Repeats the analysis for layer groups:
       - overall
       - early
       - mid
       - late
    8. Runs prompt-only controls:
       - empty_language
       - random_language

Outputs include average filters and per-sample filters used by Exp 3 and Exp 5.
The plots show level-wise W_t, layer-group W_t, wordy mirror comparisons, prompt
controls, and bandwidth-vs-residualized-logic trends.

The summary also stores `primary_mean_Gt_curve` and `wordy_mean_Gt_curve`, which
average effective bandwidth over the primary and wordy ladders for overall,
early, mid, and late filters.


================================================================================
9. EXPERIMENT 3 -- CONTROLLED POST-FUSION DRIFT
================================================================================

Main file: `experiments/exp3_fusion_drift.py`

Current design:

    1. Pre-fusion drift is computed from vision features only:
       DeltaV(omega), band-wise.
    2. Post-fusion response is computed from a late decoder layer over all
       aligned tokens, not only vision-token positions:
       DeltaZ_all, scalar.
    3. Perturbations are grouped by similar normalized DeltaV profiles.
    4. Within those groups, the code tests whether:
       DeltaZ_all follows integral W_t(omega) * DeltaV(omega).
    5. The test is run for overall, early, mid, and late W_t groups.

The `late` group is the main post-fusion branch. The other groups are controls.
The experiment also runs continuous regressions from residualized semantic logic
to DeltaZ_all and response amplification.

Grouped overlap-response correlations are split into primary, wordy, and pooled
views in addition to the legacy unsuffixed correlation payloads.

11. EXPERIMENT 5 -- SPECTRAL OVERLAP PREDICTION
================================================================================

Main file: `experiments/exp5_overlap_prediction.py`

Current primary settings:

    PRIMARY_TARGET = "loglik_volatility"
    primary layer group = late
    primary normalization = relative
    primary source alias = image_space relative branch

What it consumes:

    - W_t filters from Exp 2
    - DeltaF spectra from Exp 1
    - DeltaF_vision spectra from Exp 1 when available

What it predicts:

    S_pred = sum W_t(omega) * DeltaF(omega)

Targets:

    - loglik_volatility         primary
    - accuracy_drop             control
    - loglik_erosion            control
    - net_drop                  control
    - relative_accuracy_drop    grouped control

Branches:

    - image_space relative
    - image_space raw
    - vision_feature_space relative
    - vision_feature_space raw
    - overall, early, mid, late W_t groups

Comparable bridge:

    For visualization and standardized effect sizes, the code also emits a
    bridge analysis:

        prediction: zscore(log1p(S_pred))
        observed:   zscore(target)

    This does not replace raw overlap correlations.

Prediction-factor horse race:

    Exp 5 also regresses observed accuracy drop on:

        zscore(log1p(S_pred))
        prompt_complexity_score
        option_hardness_score

    The grouped primary branch is plotted as
    `exp5_coefficient_plot_prediction_factors.png`. This tests whether the
    physical spectral-overlap prediction remains the strongest independent
    predictor after linguistic and MCQ controls.

Grouped correlations are reported as primary, wordy, and pooled views. The
legacy `pearson_r_grouped` key remains available and corresponds to the pooled
grouped pairs for compatibility.

Plots:

    - grouped overlap vs primary target
    - sample-level overlap vs primary target
    - level-wise scatter grids
    - level-by-perturbation predicted-vs-observed bars
    - target-specific control plots for non-primary targets
    - overlap-vs-volatility plots
    - wordy-control prediction/observation comparisons

      when available

    python3 -m frequency_alignment.run_experiment \
      --experiment all \
      --config frequency_alignment/configs/local_test.yaml \
      --max-samples 5 \
      --out-dir "frequency_alignment_outputs_dryrun_5samples_$(date +%Y%m%d_%H%M%S)" \
      -v

    python3 -m frequency_alignment.run_experiment \

      --config frequency_alignment/configs/local_test.yaml \
      --max-samples 100 \
      --out-dir "frequency_alignment_outputs_local_100samples_$(date +%Y%m%d_%H%M%S)" \
      -v

    python3 -u -m frequency_alignment.run_experiment \
      --experiment 1,2,3,5 \

      --max-samples 1000 \
      --out-dir "frequency_alignment_outputs_1000samples_$(date +%Y%m%d_%H%M%S)"

    python3 -m frequency_alignment.run_experiment \
      --plot-only \
      --config frequency_alignment/configs/local_test.yaml \
      --out-dir <existing_output_dir>

17. KNOWN PRACTICAL NOTES
================================================================================

Max samples:

    If you request an odd number of GQA samples, balanced yes/no construction may
    round the effective target down to an even number. If not enough valid scene
    graphs exist for the requested constraints, the loader returns the maximum
    valid balanced set it can build.

Exp 3 perturbation subset:

    `experiments.exp3.perturbation_subset: null` means use all perturbations.
    A positive integer caps Exp 3 to the first N perturbations per sample.

Feature-space spectra:

    In local config, `extract_vision_tokens: false` avoids expensive cosine and
    Dirichlet drift calculations. Image-space DeltaF is still computed. Feature
    DeltaF is only available when the configured extraction path provides the
    needed vision features.

Existing result folders:

    Do not overwrite paper-cited output folders. Use fresh timestamped output
    directories and compare results before updating reported numbers.
